## 📚 你将学到什么

### 1. 索引的威力
- **无索引**：查询需要 245ms（全表扫描 100 万行）
- **有索引**：查询只需 2ms（B+Tree 定位）
- **性能提升**：100+ 倍！

### 2. 索引的类型
- 单列索引：`idx_user_id`
- 联合索引：`idx_user_done (user_id, done)`
- 最左前缀原则

### 3. 何时使用索引
| ✅ 应该使用 | ❌ 不应该使用 |
|-----------|-------------|
| WHERE 频繁查询的列 | 频繁更新的列 |
| JOIN 连接的列 | 区分度低的列（如性别）|
| ORDER BY 排序的列 | 小表（几千条以内）|

### 4. 索引的代价
- 占用磁盘空间
- 降低写入性能
- 需要维护

## 🎯 测试场景

程序会对比 6 种常见查询场景：

1. **精确查询** - `WHERE user_id = 5000`
2. **状态过滤** - `WHERE done = 1`
3. **联合查询** - `WHERE user_id = 5000 AND done = 1`
4. **排序查询** - `ORDER BY priority DESC`
5. **范围查询** - `WHERE created_at >= 某个日期`
6. **聚合查询** - `COUNT(*) WHERE user_id = 5000`

## 💡 常见问题

### Q: 机器性能有限，插入太慢怎么办？
**A:** 修改 `index_performance.go` 第 16 行：
```go
const TotalRecords = 100000  // 改为 10 万条
```

### Q: 如何查看 MySQL 执行计划？
**A:** 使用 EXPLAIN 命令：
```sql
EXPLAIN SELECT * FROM test_todo_no_index WHERE user_id = 5000;
EXPLAIN SELECT * FROM test_todo_with_index WHERE user_id = 5000;
```

### Q: 测试完如何清理数据？
**A:** 运行清理脚本：
```bash
mysql -u root -p todo_app_go_frame < cleanup.sql
```
